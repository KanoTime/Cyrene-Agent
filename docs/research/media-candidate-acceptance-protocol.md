# 媒体候选：大陆网络、即时撤销与容量保护最小验收协议

> 状态：测试设计，尚未执行；不授权创建媒体账号、消耗免费额度或接入正式产品代码。
>
> 目的：把“中国大陆网络必须支持”“设备撤销立即结束整通电话”“V1 必须 LiveKit E2EE、绝不降级”和“优先免费、不可静默付费”变成一个可复核的媒体候选验收协议。它补充而不取代[状态机契约](remote-call-state-machine-contract.md)、[LiveKit Cloud 大陆网络与成本闸门](livekit-cloud-mainland-network-and-cost-gate.md)和已确认的 E2EE 方案 A 密钥分发边界。

## 1. 范围与前置条件

本协议适用于任何拟承载 V1 一对一音频的媒体候选；LiveKit Cloud 是当前已研究候选，不是已锁定厂商。每次真实运行仅使用测试专用的 Android 端点、桌面端点、媒体项目和 call-scoped identity，不使用正式 Owner、真实长期设备凭据、角色内容或生产控制面数据。

要把真实运行结果计入第 6 节的“可讨论锁定”证据前，必须同时满足：

1. Owner 单独授权创建或使用该候选的测试资源，并明确本次最多可消耗的免费/付费额度；没有这项授权时，协议只可停留在文档设计。
2. Owner 已选择 E2EE 方案 A：测试须验证控制面直接分发的每通共享密钥仅在短暂进程内存和两个端点内存中出现，且不进入数据库、审计、业务日志、URL 或二维码。
3. 测试者能在中国大陆实际取得手机 5G、家庭宽带、外部普通 Wi-Fi 三类网络；“外部普通 Wi-Fi”不以企业内网、代理或专线替代。
4. 测试记录使用一次性 Case ID；开始前确认日志、录屏、抓包和分析工具不会采集音频、转写、原始 E2EE 密钥、JWT、房间名、真实设备凭据、硬件指纹或角色/用户内容。

本协议不测试来电通知、后台接听、锁屏通话、多桌面并发、角色质量或公网控制面 `watch()`；这些分别属于已确认 V1 范围外、单 Owner 规则和 CloudBase 观察。

## 2. 永不让步的验收不变量

- 每一项连通性测试均在 E2EE 已启用的前提下进行；任何明文、可选加密或“先接通后加密”的降级都立即判该候选不通过。
- 活动撤销必须同时收束本通手机和桌面的两个 call-scoped identity：控制面先封住资料领取，再等待媒体服务确认；只移除被撤销的一端不能视为“整通电话结束”。
- 已签发但未加入的旧媒体资料也必须在撤销后失效。供应商文档没有明确承诺的行为，不能因活动撤销通过而推定为通过。
- 免费额度或容量不足时，只能拒绝新媒体会话；不得自动购买、升级套餐、排队、改呼、静默重试或把失败伪装成普通挂断。它与 ¥50 的公网控制面 `Cost Protection` 是两条独立边界。
- 媒体容量变化本身不得切断已 `ACTIVE` 的 Voice Call。若媒体服务实际中断，才按既有 30 秒 `RECONNECTING` / `RECONNECT_TIMEOUT` 语义处理。
- 任何容量状态下，Device Revocation、Owner Recovery、Authorization Rebootstrap、最小安全审计和已经开始的媒体撤销工作项仍可执行。

## 3. 最小证据白名单

每个 Case 只记录以下事实，足以复核而不留下通话内容或秘密：

| 记录项 | 允许内容 | 明确禁止 |
| --- | --- | --- |
| 运行环境 | Case ID、日期、候选版本、网络类别（5G/家庭宽带/外部普通 Wi-Fi）、测试端点类别。 | 真实手机号、SSID、IP、MAC、设备型号序列号、定位信息。 |
| 阶段证据 | 请求/确认/连接/断开/撤销的时间、权威阶段、公开终态理由、客户端可见状态码。 | 音频、转写、聊天文本、角色名之外的角色内容、原始异常堆栈。 |
| 撤销证据 | 两个匿名 call-scoped identity 的“已撤销/不可加入”布尔结果、服务端确认时间。 | 房间名、identity 原值、JWT、E2EE key、API 凭据。 |
| 计量证据 | 测试前后汇总 participant-minutes、下行数据和套餐/额度状态。 | 账单账号、支付方式、完整项目标识或任何可用于接管项目的链接。 |

若排障必须查看敏感原始值，只能在本机短时查看；报告中仍仅写上述白名单事实，并在完成后按测试资源清理规则删除本地敏感日志。

## 4. 媒体候选最小真实验收矩阵

| Case | 操作 | 最低通过条件 | 失败即代表什么 |
| --- | --- | --- | --- |
| CN-5G | 中国大陆手机 5G 下建立一次 E2EE 双端音频，双方在不录音的前提下人工确认双向可听。 | 两端进入 `ACTIVE`，全程没有 E2EE 降级或单向音频。 | 该候选尚未满足大陆 5G 核心路径。 |
| CN-HOME | 家庭宽带下重复同一 E2EE 双端音频检查。 | 两端进入 `ACTIVE`，双方确认双向可听。 | 该候选尚未满足家庭网络核心路径。 |
| CN-WIFI | 外部普通 Wi-Fi 下重复同一检查。 | 两端进入 `ACTIVE`，双方确认双向可听。 | 该候选尚未满足外部 Wi-Fi 核心路径。 |
| CN-SWITCH | 在已 `ACTIVE` 的 E2EE 通话中切换可用网络（5G 与任一 Wi-Fi）。 | 原通话只使用既有 Media Session 与端点内存资料，在 30 秒内恢复；不签发新 Media Join Grant 或密钥。 | 网络切换恢复不满足 V1 的既定通话语义。 |
| REVOKE-ACTIVE | 两端已加入后撤销一台测试设备。 | 控制面先停止新资料领取，媒体服务对两个 identity 均确认撤销，双方断开，两个旧 token 都不能重新加入。 | 不满足“撤销立即结束整通电话”或旧 token 截止边界。 |
| REVOKE-PREJOIN | 两端资料已签发但均未加入，随后撤销该设备并对两个 identity 执行撤销。 | 原资料均不能首次加入；不能以“从未加入所以没有 participant”跳过验证。 | 预加入旧资料仍有加入风险。 |
| CAPACITY-PRECHECK | 在候选能无计费、权威地提前给出容量拒绝的前提下尝试发起。 | 返回 `MEDIA_CAPACITY_UNAVAILABLE`，不创建可等待通话、不签发资料、不排队、不购买。 | 已知容量不足会变成不可解释的失败或越过成本边界。 |
| CAPACITY-CONNECT | 候选只能在实际建连时报告容量不足时，发起一次受控建立。 | 已创建 Voice Call 以 `MEDIA_CAPACITY_UNAVAILABLE` 进入 `ENDED`，清除端点内存资料且不后台重试或购买。 | 建连期容量失败没有被安全、明确地收束。 |

每个网络 Case 的一次成功只是**最小功能性证据**，不是运营商级可用性统计或长期 SLA。若出现重复、一致的网络失败，或任何安全不变量失败，即停止把该候选当作满足 V1 硬要求的唯一方案；不能以短 TTL、关闭 E2EE、改用非大陆网络样本或“下次再试”把它标为通过。

### 产品语义补充检查（正式实现后）

`CAPACITY-ACTIVE` 不要求为了测试而消耗或耗尽供应商额度。它在后续状态机 Adapter 验收中验证：当一通既有 `ACTIVE` Voice Call 存在时，控制面收到“后续新会话容量不可用”的权威状态，既有通话不被产品主动结束，Device Revocation 与安全收束仍可用。它验证的是 Cyrene 的隔离语义，不是候选厂商的网络连通性证明。

## 5. 免费额度与测试成本控制

不得为了得到 `CAPACITY-*` 结果而故意耗尽当前共享免费额度。优先顺序如下：

1. 使用候选官方提供、明确不计费的容量状态或测试开关；若其能给出权威拒绝，运行 `CAPACITY-PRECHECK`。
2. 若候选只会在实际请求时告知容量状态，则只在 Owner 对单独测试项目、时间窗口和最大额度有明确授权后运行一次受控 `CAPACITY-CONNECT`；该授权不得从 ¥50 公网控制面上限或“优先免费”自动推导。
3. 如果候选没有安全、低成本的方式制造该条件，则记录为“容量失败路径尚未真实验收”，不以文档说明或模拟结果冒充真实通过，等待未来单独授权或真实自然触发时补证。

测试中一旦达到 Owner 事先设定的媒体额度，立即停止新 Case；已开始 Case 只按既定安全终态收束。这个限制不改变正式产品中“额度不足时拒绝新会话”的语义。

## 6. 通过、失败与后续产物

媒体候选只有在 CN-5G、CN-HOME、CN-WIFI、CN-SWITCH、REVOKE-ACTIVE 和 REVOKE-PREJOIN 全部通过，且容量拒绝路径已有真实或明确标记为待补的证据时，才可进入“可讨论锁定”的状态。任一 E2EE、撤销或大陆核心网络失败都直接否决它作为当前 V1 唯一媒体候选。

真实测试完成后，报告应写入 `docs/validation/`，仅引用 Case ID 和本协议的白名单证据；它必须分别结论化“通过”“失败”“未运行”与“因成本保护待补”，不能把后两者合并成通过。正式规格与实现仍须等待 CloudBase 正常使用/唤醒复核完成。
