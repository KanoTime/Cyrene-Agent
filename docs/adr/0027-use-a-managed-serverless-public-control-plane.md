# 使用托管无服务器公网控制面

Cyrene 的异地长期配对采用托管无服务器公网控制面，而不租用常驻传统 VPS，也不把控制面及其权威数据仅托管在家中 Mac。这样可以用稳定的 HTTPS/WSS 公网入口协调手机与仅建立出站连接的桌面实例，并由受控 Secret 签发每通电话的短期 LiveKit 凭据；代价是将最少的设备授权与呼叫元数据交给第三方托管。V1 的每个控制面部署只服务一个 Owner，不提供公开注册、多租户或第二个 Owner；首次初始化由一次性 Deployment Bootstrap Code 完成，后续设备通过配对或恢复加入。具体云厂商另行决定，但必须以中国大陆手机 5G、家庭宽带和普通 Wi-Fi 下的真实可用性作为首要验收条件，不能只按免费额度或海外网络表现选型。允许使用已实名认证并开通按量计费的中国大陆云账号；原型优先使用厂商提供的 HTTPS 地址，只有正式入口需要自有域名时才办理域名备案和相关配置。V1 优先采用能覆盖个位数设备正常用量的免费方案，公网控制面的月度费用硬上限为人民币 50 元，并在预计费用达到 20 元和 40 元时分级告警；达到 50 元时自动进入成本保护，拒绝新配对、新呼叫和新媒体凭据，但允许既有通话在既定上限内结束，并保留撤销、Owner Recovery 和审计查询等必要安全操作，禁止自动购买资源或提高额度。该上限不含 LiveKit 媒体、域名或应用商店费用。腾讯 CloudBase 免费环境是首选候选，阿里云函数计算是备用，但厂商必须经过可删除资源的 runnable prototype 闸门后才能锁定；原型只验证免费环境中的桌面托管实时订阅、手机 HTTPS、Secret、最少持久状态及大陆网络可用性，通过后只清理已列明的原型资源并另行进入正式规格与实现。通话音频、转写、角色记忆、模型输入输出及本地模型凭据始终不进入公网控制面。应用主动保存的数据字段、删除时机、基础设施日志残余与 90 天最小审计边界见[公网控制面最小数据边界契约](../research/public-control-plane-data-boundary-contract.md)。

## Prototype Gate

原型只使用用户保留的免费环境内、带明确原型前缀的可重建资源、虚拟设备和测试 Secret，不接入现有 CallManager、VoiceSession、移动 App 或真实 LiveKit。手机分别通过中国大陆 5G 和外部 Wi-Fi 发出 HTTPS 请求；请求须在 2 秒内送达并获确认，断线后能重新认证，最少状态能跨函数重启保存，Secret 不出现在响应或日志，个位数设备的实际使用费用预测保持在免费额度内，且三轮重复执行均通过。任一核心条件失败即停止扩建 CloudBase 原型并转评估阿里云函数计算。

实时订阅的长期门禁必须模拟真实桌面使用，而不是要求 Owner 连续 72 小时不合盖：在不少于 72 个日历小时的正常使用窗口内，至少累计 12 个桌面清醒且订阅已就绪的小时，并覆盖至少 3 次真实 Desktop Suspension / Wake Reconciliation。每次唤醒都必须由原型显式关闭旧订阅、重新认证并新建订阅，而非把 SDK 的自动重建当作恢复；新订阅取得初始快照和一次 30 秒内的无内容脉冲确认后才计入有效观察。清醒段内字段白名单不能越界、脉冲不能丢失或超时；若出现实时错误，必须记录并以显式新订阅取得后续成功证据，否则失败。资源点只按已就绪的清醒连接时间和短函数脉冲推导，环境当日总增量只作为保守上界，不能把合盖时间伪装成持续连接成本。

验证结束后只能删除明确列出的原型函数、路由、集合、测试用户、日志和测试 Secret，并逐项复核；免费环境本身必须保留，销毁环境只有在单独列明资格损失后取得 Owner 明确确认时才允许。仓库只保留结论、测量数据及正式接口发现。

## Prototype Result — 2026-07-22

腾讯 CloudBase 体验版的“常驻云函数承载 WebSocket”形态在网络和功能上通过、在长期成本上失败，因此不作为 V1 实现；CloudBase 本身随后改用托管数据库 `watch()` 继续验证。临时环境位于上海地域，只使用虚拟设备、测试配置和文档型数据库；Android 手机经中国大陆 5G 与外部 Wi-Fi 均能访问默认 HTTPS 域名。Mac 三轮测试中，HTTPS 写入确认耗时 125–477 ms、持久化读取耗时 137–270 ms、携带测试凭据重新建立 WebSocket 并收到确认耗时 316–808 ms，全部低于 2 秒。无凭据 WebSocket 请求未获协议升级；函数重新部署后仍能读取先前记录。测试配置可由函数环境变量读取，但其值未进入业务响应。测试期累计 7 次数据库读取、6 次写入、33 次 HTTP 网关调用和 1 GBs 云函数资源，控制台合计计入 0.53 资源点。

失败原因是常驻 WebSocket 的计费模型，而不是大陆网络可达性。CloudBase 的 WebSocket 连接会在连接生命周期内占用云函数实例。按原型的最低 128 MB 内存计算，一台桌面连续在线 30 天消耗 `0.125 GB × 2,592,000 s = 324,000 GBs`；按 2026-07-22 官方价格 `0.11108 点/GBs` 约为 35,990 点/月。体验版每月只有 3,000 点，约只能覆盖单台桌面 60 小时；三台桌面理论值约 107,970 点（约人民币 107.97 元），超过已确认的人民币 50 元硬上限。体验版又不能开启超限按量付费，因此不能依靠成本保护弥补这一缺口。计价依据为[腾讯 CloudBase 资源点价格文档](https://cloud.tencent.com/document/product/876/127357)。

原型还发现以下正式接口约束：HTTP 与 WebSocket 云函数都以启动脚本拉起进程并监听 9000 端口；默认 HTTPS 域名需要显式配置 `WEB_SCF` 路由；WebSocket 路由可转发自定义鉴权请求头，但握手被应用拒绝时网关可能对客户端呈现普通 HTTP 响应而非保留应用返回的 401；文档集合需要在首次 SDK 写入前显式创建；路由 QPS 限制会以 429 `EXCEED_RATELIMIT` 明确拒绝请求。后续候选必须验证常驻桌面连接的完整月度成本，而不能只用短连接调用量估算。

## Prototype Cleanup Incident — 2026-07-22

前次原型清理错误地销毁了整个 CloudBase 免费体验环境，而不是只删除函数、路由、测试数据、日志与 Secret。腾讯云客服随后确认该免费资格无法恢复，用户另行创建了新体验环境 `cyrene-agent-d2gfztehj201e3df3`。这是原型清理边界的执行错误：清理要求不再授权销毁免费环境容器本身。今后任何免费或一次性资格环境均必须默认保留；只能删除可重建的原型资源，销毁环境必须在单独列明资格损失后再获得 Owner 明确确认。

## Prototype Result — Managed Database Watch, 2026-07-22

第二次可删除原型将范围缩小为一台虚拟桌面和三个虚拟移动设备，用 CloudBase 托管文档数据库 `watch()` 代替常驻 WebSocket 云函数。成本与时延方向通过：桌面只建立一条托管实时连接，初始快照在 1.44–1.91 秒到达；短云函数写入后约 171 ms 到达桌面。三个移动设备并发呼叫时，仅一个在 87 ms 内成功，其余两个分别在 134 ms 和 65 ms 内收到 `OWNER_BUSY`；同一请求重放返回 `IDEMPOTENT_REPLAY`。热函数调用为 65–134 ms，一次冷调用为 1,019 ms，都在 3 秒上限内。

安全核心闸门失败：将桌面用户标记为 `BLOCKED` 约 16 秒后，既有 `watch()` 仍在后续写入后约 172 ms 收到完整文档变化；只有新登录会立即被 `user_blocked` 拒绝。因此 CloudBase 运输层 token 会在撤销后继续提供读能力，不能直接用 `watch()` 传递权威呼叫状态或任何敏感数据。另外，`@cloudbase/js-sdk` 3.6.3 在 Node 24 下必须显式选择官方 Node 适配器；其在云函数中还出现“条件更新成功，管理端 `doc.get()` 返回 `INVALID_CREDENTIALS`”的不一致，正式路径不得依赖该组合。因即时撤销已失败，不再为这个“直接传递权威状态”的形态执行 72 小时稳定性试验，也不能根据当时尚未结算的 0 点用量面板声称已证明月度免费。

原型一次性代码保存在抛弃式分支 `codex/prototype-cloudbase-watch`（提交 `8e62ff7`）作为主要证据，不合入主分支。云端函数、原型集合和四个外部测试用户均已删除并复核；新 CloudBase 环境保留且状态为 `NORMAL`。

## Prototype Result — Opaque Wake Signal, 2026-07-22

第三次可删除原型按 ADR-0037 将唤醒与权威读取分层。唤醒文档仅有 `_id`、`desktopUid`、`wakeNonce`；权威集合为 `ADMINONLY`，普通桌面身份直接读取返回 `DATABASE_PERMISSION_DENIED`。有效测试设备凭据可获得来电设备和动态角色名；撤销操作立即把活动呼叫置为 `ENDED / DEVICE_REVOKED`，随后使用同一凭据的读取只返回 `DEVICE_REVOKED`。

将 CloudBase 桌面用户置为 `BLOCKED` 后，已建立的 `watch()` 在撤销及撤销后额外唤醒时各收到一次变化，但四次快照均仅有允许的三个字段，客户端字段白名单结果为 `schemaViolation=false`；新登录仍立即返回 `user_blocked`。因此已接受的有限时序元数据残留不会变成数据或操作权。安全分层闸门通过，但在最终锁定 CloudBase 前仍需完成符合真实合盖/唤醒行为的实时连接计量/稳定性观测，并在正式 HTTPS 路由中集成 Credential Family 轮换与 LiveKit 参与者移除。

## Prototype Observation Correction — 2026-07-22

最初把这一门禁写成“家中 Mac 一条 `watch()` 连续 72 小时不断开”是不合理的：它要求 Owner 放弃正常通勤合盖，也与 ADR-0031 的产品边界冲突。首段运行在 Owner 批准的合盖返家期间出现 `transport pause`、`REBUILD_WATCH` / `QUERYID_INVALID_ERROR`、一次函数调用失败和一次脉冲超时；原始状态、日志和资源点基线保留为证据，不能被写成连续通过，也不因 Owner 已声明的暂停而归咎为产品失败。

这段证据反而确认了正式恢复不能依赖 CloudBase SDK 自动重建 `watch()`。后续原型改按本 ADR 的“72 日历小时 + 12 清醒小时 + 3 次真实唤醒复核”门禁运行；合盖时桌面本来就不可接听，唤醒后只有显式新订阅和权威读取成功才重新可用。原型资源继续保留到这项修订观察完成，仍不得删除 CloudBase 环境。

修订观察的首个 epoch 在累计 3.361 清醒小时后，本机监测进程没有写出终态摘要便消失；截至最后一次更新，20 次脉冲均得到确认，字段越界、调用错误、脉冲超时和实时订阅错误均为零。它被如实标记为 `OBSERVATION_INTERRUPTED`，既不是旧“连续开盖”任务的恢复，也不是 CloudBase 通过或失败结论。任何下一轮都必须使用独立状态文件和同一修订门槛，不得续算、重写或用自动重启掩盖这一中断；旧连续实验永久排除在门禁之外。

本原型发现权威函数不能使用 `@cloudbase/js-sdk` 3.6.3 的管理读取路径；实测改用 `@cloudbase/node-sdk` 4.0.3 并将其旧 Axios 依赖 override 为 1.18.1 后，读写通过且 `npm audit --omit=dev` 为 0。该 SDK 版本当前属于 npm `next` 标签，因此正式实现需固定并回归完整依赖树，不直接复制原型配置。一次性代码和详细证据保存在同一抛弃式分支（提交 `0cc4f61`，清理复核 `877f55e`）。原型函数、两个集合和外部测试用户已删除并复核；CloudBase 环境保留、到期时间仍为 2027-01-22 23:59:59，状态为 `NORMAL`。

## Owner 授权的受限 Beta 提前部署（2026-07-23）

当前独立 `normal-use-wake-reconciliation-v1` epoch 累计 14.412 个清醒小时，超过 Owner 重新指定的“允许开始部署”最低门槛 12 小时；86 次脉冲中最近已完成的 85 次均有确认，字段越界、脉冲超时和 `watchErrors` 为零。期间一次函数调用错误及五次订阅重建失败均保留，并在随后通过显式新订阅、初始快照和成功脉冲恢复；当前只覆盖一次 Wake Reconciliation，仍未达到原定 72 日历小时与三次唤醒复核。

Owner 明确授权在不终止上述观察的前提下，启用正式 HTTP Access Service、部署 `cyrene_device_authorization_control` 并创建 `/v1` 路由，用于尽早进行单 Owner、单桌面、多移动设备的受限 Beta 配对验收。该授权只放宽“何时可以开始最小正式资源部署”，**不把 CloudBase 候选标记为通过、不替代剩余稳定性/成本结论，也不授权删除环境或观察原型资源**。若后续完整观察失败，停止扩大正式使用并按单独批准的精确资源清单回滚；领域模型与客户端安全实现不回退。
